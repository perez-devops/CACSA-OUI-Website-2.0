# Professional Design Workflow

Use this workflow for medium and large projects.

## Phase 1 — Discover

Understand:
- problem
- users
- context
- goals
- constraints
- differentiator

Define the primary user journey.

## Phase 2 — Strategy

Define:
- product positioning
- information hierarchy
- primary conversion/action
- content priorities
- trust requirements
- page purpose

Do not start by choosing random sections.

## Phase 3 — Structure

Create:
- sitemap
- user flows
- page hierarchy
- content hierarchy
- navigation model

Every page should have a clear job.

## Phase 4 — Visual direction

Define:
- brand personality
- typography direction
- color strategy
- imagery direction
- spacing philosophy
- shape language
- motion language

The visual system must communicate the same personality across the product.

## Phase 5 — Design system

Define:
- design tokens
- type scale
- color roles
- spacing scale
- radius
- elevation
- motion
- breakpoints
- reusable components
- states

## Phase 6 — Build

Implement:
- foundation
- layout
- components
- interactions
- backend/API where required
- real states

Do not leave production-critical states until the end.

## Phase 7 — Harden

Check:
- validation
- security
- error handling
- accessibility
- performance
- responsive behavior
- edge cases

## Phase 8 — Critique

Use the Design Critic skill.

Question:
- What feels generic?
- What is unnecessary?
- What competes for attention?
- What feels inconsistent?
- What can be simplified?
- What can become more distinctive?

Then refine.

## Phase 9 — QA

Test:
- navigation
- forms
- authentication
- CRUD
- permissions
- loading
- empty
- error
- success
- mobile
- desktop
- accessibility
- performance

## Phase 10 — Deploy

Verify:
- production build
- environment configuration
- database migrations
- production API
- CORS
- assets
- authentication
- secrets
- monitoring/logging where appropriate

Perform production smoke tests.

## Phase 11 — Final audit

Do not declare "done" because the build succeeds.

Ask:

Would a senior product designer approve this?

Would a senior frontend engineer be proud of this?

Would a brand strategist recognize a coherent identity?

Would a first-time user understand it quickly?

Would this product look credible beside work from a top-tier digital product team?

If not, iterate.
